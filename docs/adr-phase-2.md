## ADR-0008 — Generate the winget projection from the installed App Installer package

- **Date**: 2026-07-25
- **Affected**: `TODO.md` M0, `WingetComSource`
- **Status**: Accepted

### Decision

The build discovers `Microsoft.Management.Deployment.winmd` in the newest installed
Microsoft Desktop App Installer package and invokes the C++/WinRT compiler supplied by
the selected Windows SDK. Generated headers are written under the project's intermediate
directory and added to the core library's include path.

The projection is generated by a dedicated MSBuild target. The target reports a clear
build error when either Desktop App Installer or the SDK compiler is unavailable.

### Reason

- Desktop App Installer is already a runtime prerequisite for querying winget packages,
  so its installed metadata is the authoritative local source.
- The selected Windows SDK supplies both the compiler and the Windows metadata references
  needed by the generated projection.
- This keeps the project free of a package-manager dependency whose only purpose would
  be supplying generated headers.
- Intermediate output is configuration- and architecture-specific, preventing parallel
  builds from writing to the same directory.

### Consequences

- Developers and CI images must have Microsoft Desktop App Installer installed.
- A Store package update can change the input metadata. The projection is therefore
  generated during each non-design-time build instead of being committed.
- Cross-building ARM64 continues to use the x64 host compiler; the generated C++ headers
  are architecture-independent.
